# 카드 점수 보정 (2026-11, 상위 랭커 선택 + 랭커 공략)

오버레이가 카드 보상 화면에서 추천하는 카드가 **상위 랭커가 실제로 집는 카드**에 더 가까워지도록 카드 점수표를 다시 맞췄습니다.
랭커 런 데이터로 "무엇을 집는지"를 재고, 검증 가능한 상위 플레이어 공략(Baalorlord, Jorbs)으로 "왜 그렇게 집는지"를 확인했습니다.
랭커 선택과 100% 맞추는 것은 목표가 아닙니다(§7).

- 바꾼 것: 티어 14장 한 단계 이동, 카드 `baseAdjust`(새 필드, −15~+15점), 막별 역할 긴급도(`urgency`) 15칸 중 5칸.
- 결과(학습에 쓰지 않은 플레이어 기준): 랭커와 같은 카드를 고른 비율 **43.2% → 47.2%**, 시험 로그우도 −1.262 → −1.196,
  점수 차가 10점 이상인 "확신 화면" 일치율 49.7% → 51.3%. 시뮬레이터의 덱 품질 지표는 거의 그대로입니다(§6).
- **후속 보정(§9.1)**: 보조 태그 포화 버그 수정, 아키타입 역할 12장 정리, `buildDuplicateFactor` 0.3·카드별 `dupFactor` 31장, 3막 스킵 기준 50, 신뢰도 0.45 카드 4장 수정 뒤 다시 맞췄습니다.
  지금 팩은 카드 378장에 `baseAdjust`가 있습니다. 학습에 쓰지 않은 플레이어 일치율은 43.8% → **47.2%**(PR #25와 같은 수준),
  시험 로그우도 −1.255 → −1.192, 확신 화면 50.2% → 51.7%입니다. 바뀐 것은 덱 모양입니다: 빌드 카드 중복 1.47 → 1.73장(랭커 1.87), 3막 스킵 58% → 50%(랭커 48%), 치명적 이탈 2.8% → 1.9%.
- 재현: [`tools/CardCalib/`](../../tools/CardCalib/pipeline.py). 랭커 런 파일은 이 PC에만 있고 저장소에 넣지 않습니다.

## 2. 점수 구조와 바꾼 곳

카드 점수 = 기본 점수(티어 값 + 강화 보정 + **`baseAdjust`**) + 빌드·콤보·역할 부족(need)·코어 보정 − 빌드 이탈·중복·희석·포화 감점.

```text
기본 점수 = 티어 값(S80 / A65 / B50 / C35 / D20) + upgradedDelta + baseAdjust   ← 이번에 추가
need      = 25 × 부족한 정도 × urgency[막][역할] × 카드의 역할 강도              ← urgency 다섯 칸 수정
```

`baseAdjust`는 같은 티어 안의 차이를 표현합니다. 배지는 여전히 티어 글자만 보여 주고, 점수 설명에 "랭커 선택 보정 +N"으로 나옵니다.
범위는 ±15이고, 한 티어 간격(15점)보다 크게 바꿔야 하면 티어 글자를 바꿉니다([`DATA_SCHEMA.md`](../DATA_SCHEMA.md)).

## 4. 티어 글자 이동 (14장, 모두 한 단계)

v2 티어([`v2-stats/tiers.md`](v2-stats/tiers.md))는 부트스트랩에서 한 등급이 80% 이상 나와야 반영했기 때문에, 경계에 걸친 카드는 "불확실"로 원래 값에 머물렀습니다.
예를 들어 리젠트 `WROUGHT_IN_WAR`는 80/80위인데도 B에 남았습니다. 이번에는 **방향 규칙**을 썼습니다.

- 위로 갈 확률이 80% 이상이면 재표본 분포의 20% 분위 등급으로, 아래로 갈 확률이 80% 이상이면 80% 분위 등급으로 옮깁니다.
- v2에서 이미 데이터로 정한 카드(변경·확인)는 95% 이상일 때만 움직입니다. 같은 데이터로 두 번 흔들지 않기 위해서입니다.
- 플레이어를 둘로 나눈 두 반쪽에서 **모두 같은 이동**이 나온 카드만 최종에 넣었습니다(14장). 나머지 차이는 `baseAdjust`로만 흡수합니다.

## 5. 카드별 `baseAdjust`

조건부 로짓으로 "엔진 점수만으로는 설명되지 않는 랭커의 선호"를 카드마다 추정했습니다.

```text
u(카드) = β × 엔진 점수 + δ[카드]        u(스킵) = β × 스킵 기준점 + s[막]
baseAdjust = 15 × tanh((δ / 0.08) / 15), 반올림
```

- β(점수 1점의 로짓 값)는 0.032로 추정됐지만, 엔진 점수의 잡음 때문에 작게 나오는 값이라 그대로 나누면 보정치가 커집니다.
  그래서 **0.08로 고정**(로짓 1 = 12.5점)하고 tanh로 ±15에 부드럽게 묶었습니다. 2차 검토 권고를 따랐습니다.
- δ에는 L2 벌점(λ=1)을 줘서 표본이 적은 카드는 0 쪽으로 줄어듭니다. 우수 플레이어만이 아니라 168명 전부의 승패 런을 씁니다.
- 제시 30회 미만 카드는 바꾸지 않습니다. 티어를 옮긴 카드와 v2에서 데이터로 정한 카드는 ±10까지만 씁니다.
- **공략 반감 규칙**: 두 공략이 모두 데이터와 반대 방향으로 한 등급 이상 떨어져 있으면 보정치를 절반으로 줄입니다. 단, 아키타입 카드와 "1막 전용" 판정 카드는 예외입니다(랭커가 특정 빌드에서만 집거나, 공략도 1막에만 높게 보는 카드). 19장에 적용됐습니다(예: `FLECHETTES` 추정 −13점 → 최종 −6, `MEMENTO_MORI` 추정 −18점 → 최종 −8).
- **패치된 카드**: v0.108~v0.111 패치 노트에 있는 카드(네크로바인더·리젠트·무색 24종)와, v0.107과 v0.111 사이 랭커 선택률이 15%p 이상 차이 나고 |z| ≥ 2.5인 카드 27장(예: 사일런트 `WELL_LAID_PLANS` 29% → 62%, 디펙트 `FTL` 49% → 23%)은 **v0.107.x 런으로만** 판정합니다. 로짓에서는 이 카드들의 v0.111 화면에 별도 변수를 둬서 화면을 버리지 않습니다. 이 팩은 v0.107.1용이므로, 게임이 v0.111로 바뀌면 이 카드들을 다시 봐야 합니다.

PR #25에서는 캐릭터마다 74~78장, 모두 382장에 보정치가 붙었고 그중 98장이 ±10 이상이었습니다.
후속 보정(§9.1) 뒤 다시 맞춘 지금 팩은 캐릭터마다 72~78장, 모두 **378장**이고 그중 95장이 ±10 이상입니다. 큰 것들은 §11 표에 있습니다.

### 6.3 늘어난 이탈은 랭커도 하는 선택인가

치명적 이탈은 "아직 없는 코어·핵심 카드를 두고 다른 카드를 집은 경우"입니다. 시뮬레이터 이탈 사례마다 같은 두 카드가 함께 나온 랭커 화면에서 랭커가 어느 쪽을 집었는지 셌습니다.

|---|---|---|---|---|
| 보정 전 | 433 | 203 | **101** | 129 |
| PR #25 최종안 | 466 | 273 | 82 | 111 |
| **후속 보정 (§9.1)** | 488 | 309 | **51** | 128 |

랭커와 반대인 이탈은 오히려 줄었습니다. 늘어난 것은 랭커도 하는 선택입니다. 예: `CLOAK_AND_DAGGER` > `UNTOUCHABLE`(랭커 24:6), `BLADE_DANCE` > `DAGGER_THROW`(18:1), `TREMBLE` > `SETUP_STRIKE`(15:3).
지금의 아키타입 정의가 일부 카드(단검 투척, 녹은 주먹 등)를 실제보다 핵심으로 보고 있다는 뜻이기도 했습니다.
후속 보정에서 이 쌍들과 엔진이 아키타입 안에서 지나치게 고르던 카드의 역할을 정리했고(§9.1), 랭커와 반대인 이탈이 82 → 51건으로 줄었습니다.
랭커 표본이 있는 이탈 360건 중 309건(86%)은 랭커도 같은 카드를 집었습니다(예: `WHITE_NOISE` > `COOLHEADED` 12:1, `PARSE` > `SNAP` 13:0, `BLUR` > `HAZE` 13:3).

## 7. 왜 100% 맞추지 않는가

- **엔진은 항상 최고점 하나만 고릅니다.** 랭커가 반쯤 집는 카드는 엔진에서 "대부분 1등"이나 "대부분 2등"이 되기 쉽습니다. 그래서 카드별 선택률은 랭커보다 극단적으로 나옵니다(예: `WHITE_NOISE` 랭커 51%, 엔진 2% → 65%).
- **랭커끼리도 다르게 고릅니다.** 같은 카드가 같은 화면에 나와도 플레이어마다 선택이 갈립니다. 화면의 절반 이상은 1·2위 점수 차가 10점 미만입니다.
- **엔진이 보지 못하는 정보**가 있습니다. 다음 경로, 남은 체력, 보스, 포션, 랭커의 계획 등입니다.
- **과적합 위험.** 카드마다 자유롭게 맞추면 학습 반쪽에서는 더 맞지만, 다른 플레이어에서는 좋아지지 않았습니다(1차 검토). 그래서 보정치를 줄이고 묶고, 두 반쪽이 동의한 티어 이동만 넣었습니다.
- **버전이 섞여 있습니다.** 런의 절반 이상이 v0.111입니다. 패치된 카드는 v0.107로만 판정했지만, 표본이 그만큼 줄어듭니다.

## 8. 공략과 데이터가 다를 때

- **데이터가 우선**입니다. 랭커가 실제로 그렇게 집기 때문입니다. 다만 두 공략이 모두 반대이면 보정 폭을 절반으로 줄였습니다(§5).
- `ACROBATICS`(곡예): 두 공략 모두 최상위(S+/S)이지만 랭커는 43%만 집습니다. 공략이 높게 보는 이유(교활 카드가 있으면 에너지까지 얻음)는 조건부라서 빌드 점수가 따로 담당합니다. 그래서 기본 점수는 B로 내렸습니다.
- `WROUGHT_IN_WAR`(전장의 생존자): Jorbs는 A(일반 카드 한 장치고 피해가 많다는 이유), Baalorlord는 C입니다. 랭커 선택률은 4%라 C로 내렸습니다.
- `SNAKEBITE`(뱀 물기): Jorbs S+(1막 보스용), Baalorlord B+입니다. 랭커 14%, 엔진 36% → 21%(보정 −10). "1막 전용" 판정 카드라 반감 규칙을 쓰지 않았습니다.
- 1막 스킵 규칙(`skip.t0[1]=45`, 기본 카드 편향)은 바꾸지 않았습니다. 막별 스킵 비율(랭커/엔진)은 15/0 → 15/1, 36/25 → 36/29, 48/55 → 48/58이었고, 후속 보정(3막 기준 52 → 50) 뒤 15/1, 36/28, 48/50입니다.

## 9. 후속 보정과 남은 차이

### 9.1 후속 보정 (2026-11, PR #25 다음)

PR #25 뒤 남은 세 가지(중복 부족, 3막 스킵 과다, 아키타입 역할)와 "가끔 이상한 카드를 추천한다"는 체감을 리플레이 진단으로 따라가 고쳤습니다. 고친 뒤 `pipeline.py fit`을 다시 돌려 팩 전체를 다시 맞췄습니다.

1. **신뢰도 0.45 카드가 추천 배지를 못 받음.** `RecommendationEngine`은 신뢰도 0.5 미만 카드를 추천 후보에서 뺍니다.
   초안 시절 0.45가 남아 있던 네크로바인더 `NEUROSURGE`·`LETHALITY`·`CALL_OF_THE_VOID`, 리젠트 `HEIRLOOM_HAMMER`는 1위 점수를 받고도 추천되지 않았습니다.
   이제 `fit`은 제시 30회 이상으로 보정한 카드의 신뢰도 0.45를 0.65로 올립니다. 엔진 선택률: `NEUROSURGE` 6% → 64%(랭커 67%), `LETHALITY` 1% → 81%(56%), `CALL_OF_THE_VOID` 0% → 39%(41%).
2. **보조 태그 포화 감점.** 빌드 카드가 빌드의 needs.tag 말고 다른 태그(`ORB`, `DRAW`, `BLOCK` 등)도 만들면 그 태그로 시너지 점수의 최대 70%를 깎였습니다. 자세한 것은 [`DECK_SIM.md`](DECK_SIM.md) §3.2.
3. **아키타입 역할 정리 (12장).** core·enabler·payoff는 빌드가 자리 잡으면 시너지 바닥 점수를 받기 때문에, 랭커가 빌드 안에서도 잘 안 집는 카드가 거기 있으면 `baseAdjust`로 깎아도 계속 추천됐습니다.
   - support로 내림(11장): 디펙트 `BALL_LIGHTNING`(번개), 아이언클래드 `ARMAMENTS`(방어)·`SETUP_STRIKE`(타격), 네크로바인더 `SCOURGE`(파멸), 리젠트 `ASTRAL_PULSE`(별)·`HIDDEN_CACHE`(별 소비)·`WROUGHT_IN_WAR`(대장간)·`COLLISION_COURSE`(창조), 사일런트 `HAZE`(독)·`DAGGER_THROW`·`UNTOUCHABLE`(교활·버리기, `essentialTarget` 3 → 2).
   - enabler로 올림(1장): 네크로바인더 `LETHALITY`(영체).
   - 뺌: 디펙트 `COMPACT`(상태이상 축이 필요한 카드)를 `dark_orbs`·`orb_variety` support에서.
   - 1차 시도에서 `GUIDING_STAR`, `POKE`, `SPOILS_OF_BATTLE`, `BARRAGE`, `FEAR`까지 내렸을 때는 이미 `baseAdjust`로 랭커 이하로 내려가 있던 카드가 이중으로 깎여 이탈이 늘었습니다. 그래서 §6.3에서 지목됐거나 엔진이 빌드 안에서 지나치게 고르던 카드만 옮겼습니다.
4. **빌드 카드 중복.** 팩의 `buildDuplicateFactor` 0.4 → 0.3. 그리고 `fit`이 카드별 `dupFactor`를 맞춥니다(`fit_dupfactors`).
   - 대상: 이미 한 장 이상 가진 상태로 다시 나온 화면이 15개 이상(플레이어 4명 이상)이고, 그 화면에서 엔진과 랭커의 "두 장째 선택" 수가 4 이상 차이 나는 카드.
   - 학습 플레이어를 다시 둘로 나눠 **두 반쪽 모두** 일치 수가 줄지 않고 차이가 줄어드는 값만 고릅니다(격자 0.2~2.5).
   - 엔진은 항상 1위 하나만 고르므로 자주 겹쳐 집는 카드도 엔진이 더 많이 고를 수 있습니다. 그래서 `dupFactor`를 올리는 것(중복 억제)은 랭커의 두 장째 선택률이 12% 이하인 카드에만 허용합니다.
   - 결과: 31장(내림 30, 올림 1: `STAMPEDE` 1.3 → 2.5). 예: `BACKFLIP` 1 → 0.2(랭커 109 / 엔진 12, 275화면), `FOOTWORK` 1.3 → 0.2, `DEFY` 1 → 0.3, `PERFECTED_STRIKE` 1 → 0.3.
   - 효과 비교(같은 설정으로 `cv`, `--dupfactor 0`은 카드별 보정을 끔, `--dup-floor`는 격자 하한):

     | 안 | 시험 일치율 | 시험 로그우도 | 확신 화면 | 시뮬레이터 중복 (엔진/랭커) | 리플레이 일치율 |
     |---|---|---|---|---|---|
     | 카드별 보정 없음 | 47.1% | −1.1947 | 51.6% | 1.69 / 1.87 | 49.2% |
     | **하한 0.2 (채택)** | **47.2%** | **−1.1921** | **51.7%** | **1.73 / 1.87** | **49.5%** |
     | 하한 0.4 | 47.2% | −1.1926 | 51.7% | | |
     | 하한 0.6 | 47.2% | −1.1933 | 51.7% | | |

     두 반쪽 모두 카드별 보정을 켰을 때 시험 로그우도가 나아졌고(A −1.1911 → −1.1896, B −1.1997 → −1.1955), 하한을 올릴수록 그 이득이 줄었습니다. 그래서 0.2에 닿은 카드가 13장이어도 하한을 올리지 않았습니다.
     이탈률(8.7% / 치명적 1.9%)은 두 안이 같습니다. 중복 회복의 대부분은 `buildDuplicateFactor` 0.3과 다른 수정에서 오고, 카드별 보정은 그 위에 조금 더합니다.
5. **3막 스킵 기준** 52 → 50. 2·3막 즉시 피해·광역 긴급도를 낮춰 3막 카드의 need 점수가 줄어든 만큼 되돌린 것입니다.

결과는 §6.1~6.3의 "후속 보정" 행에 있습니다. 전체 테스트 1,945개가 통과합니다.

### 9.2 남은 차이와 다음 할 일

- **`dupFactor` 카드 선택은 표본에 민감합니다**: 2겹 교차검증에서 두 학습 반쪽이 고른 카드는 10장 / 24장이고 겹치는 것은 3장(방향은 모두 같음)입니다. 고른 값은 시험 플레이어에서도 조금 낫지만(§9.1), 어느 카드가 뽑히는지는 데이터가 늘면 바뀔 수 있습니다.

- `cardtable.py` 인자: `base.all.csv main.all.csv main.fit.json 공략.csv 출력.md` (앞의 둘은 `eval` 결과).
