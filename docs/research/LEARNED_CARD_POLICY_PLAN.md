# 카드 선택을 "학습형"으로 바꾸는 계획

작성 2026-11-09. 아직 구현 전. 코드 기준은 origin/main (7125fe6).

## 0. 한 줄 요약

진짜 강화학습(게임을 수백만 번 시뮬레이션해서 스스로 배우기)은 지금 불가능하다. 전투 시뮬레이터가 없어서 "이 덱이 이겼다/졌다"를 만들어 낼 수 없기 때문이다.
대신 이미 가진 **랭커 2,155판(1,067승 / 1,088패, 픽 화면 36,461개)** 으로 두 모델을 학습한다.

1. **픽 모델 (모방학습, behavior cloning)**: "이 덱 상태에서 랭커라면 무엇을 고르나"를 예측한다.
2. **승률 모델 (가치 함수, value model)**: "이 덱 상태로 이 런을 이길 확률"을 예측한다.

그리고 둘을 합쳐서 "랭커가 고를 법하고, **이 카드를 넣으면 승률이 올라가는**" 카드를 추천한다.
이 결합은 오프라인 강화학습에서 쓰는 "이득 가중 모방학습(advantage-weighted regression, AWR)"과 같은 발상이다.

## 1. 지금 방식 (요약)

`CardScorer.cs` 는 카드마다 점수 조각을 **더한다**.

| 조각 | 뜻 | 대표 숫자 |
|---|---|---|
| base | 티어 값 (S80 … D20) + `baseAdjust`(데이터로 보정) | 티어 5단계 |
| build | 빌드(아키타입)에 들어가는 카드면 `20 × 커밋 × 역할가중치`, 최대 25 | 코어 1 / 페이오프 .9 / 인에이블러 .7 / 서포트 .5 |
| core_priority | 빌드 코어가 아직 없으면 코어 카드 가산 | 최대 15 |
| combo | 짝 카드를 갖고 있으면 가산 | 최대 15 |
| need | 덱에 부족한 역할(전방 딜, 광역, 방어, 스케일링, 드로우, 에너지) 채우기 | `25 × 부족분 × 막별 긴급도` |
| 감점들 | 빌드 밖 카드 −10, 중복 −15×…, 덱 비대 −1.5/장, 파워 과다 −4 | |
| 스킵 | `t0[막]`(45/52/50) + 덱이 크면 가산 | 카드가 스킵보다 0.5 이상 높아야 추천 |

손으로 정한 숫자가 약 2,500~3,000개이고, 그중 약 410개(`baseAdjust` 378, `dupFactor` 31, 긴급도 5칸)만 데이터로 맞췄다.
보정 모델(`tools/CardCalib/clogit2.py`)은 "엔진 총점 × β + 카드별 보정값 δ" 라는 단순한 형태라서, **카드와 덱의 상호작용(이 카드가 이 덱에서 특히 좋다)** 은 사람이 짠 규칙에만 들어 있다.

현재 성적 (랭커 픽을 맞히는 비율, 학습에 안 쓴 플레이어 기준): **top-1 47.2%, 로그우도 −1.192/화면**.
랭커 픽이 엔진 1~2위 안에 드는 비율은 82~84%.

### 왜 "그냥 더하기"가 한계인가

더하기 모델은 "A 카드는 +10, 덱이 독 빌드면 +15" 처럼 효과가 독립이라고 가정한다.
실제로는 "덱에 촉매(Catalyst)가 있으면 독 카드 가치가 두 배" 같은 **곱셈·조건부 효과**가 많다.
사람이 규칙을 하나씩 추가하면 숫자가 계속 늘고, 서로 충돌하고(이번 달에만 saturation, BuildSecured, core-first gate 수정), 패치 때마다 다시 손봐야 한다.
학습 모델은 이런 상호작용을 데이터에서 직접 뽑아낸다.

## 4. 추천 경로: E (모방학습 → 승률 모델 → 결합)

### 4.1 핵심 아이디어

```
점수(카드) = log P_랭커(카드 | 상태)  +  λ · [ V(상태 + 카드) − V(상태) ]
             └─ 픽 모델 (B)               └─ 승률 변화 (C)
```

- 픽 모델이 "말이 되는 후보"를 고르고, 승률 모델이 그 안에서 "실제로 이기는 덱 쪽"으로 민다.
- λ = 0 이면 순수 모방학습, λ 를 키울수록 결과 기반(RL 쪽)이 된다. λ 는 검증 데이터로 정한다.
- 화면에는 지금처럼 순위 + "승률 +2.1%p" 같은 이유를 보여 줄 수 있다.

### 4.2 모델 형태

**픽 모델**: 화면마다 후보(카드 3장 + 스킵) 중 하나를 고르는 소프트맥스(지금의 조건부 로짓과 같은 틀).
후보 점수 = 작은 신경망 `f(덱 요약, 카드 특징, 상호작용)`.

- 덱 요약: 카드별 임베딩(카드 ID → 16차원 벡터)의 합/평균 (DeepSets), 역할 공급량·부족분, 아키타입 커밋, 덱 크기, 막/층, HP 비율, 캐릭터, 유물 임베딩 합, 게임 버전 플래그.
- 카드 특징: 카드 임베딩, 티어, 비용, 타입, 강화 여부, 이미 가진 장수.
- 상호작용: `카드 임베딩 · 덱 임베딩` (내적) — 이게 "이 덱에서 이 카드가 특히 좋다"를 배우는 부분.
- **기존 엔진 점수 조각도 입력으로 넣는다** (build, need, combo …). 처음부터 다 배우게 하면 데이터가 모자라고, 엔진 지식을 출발점으로 쓰면 "엔진 + 학습된 보정" 이 된다(잔차 학습). 엔진 점수만 쓰면 지금 모델과 같아지므로 기준선도 자연스럽게 확보된다.

**승률 모델**: 상태 → P(이 런 승리). 같은 덱 요약 + 막/층/HP/최대HP/골드.
승패만 보면 신호가 약하므로 보조 목표를 같이 학습한다 (다중 과제):
- 이번 막을 살아서 넘기나 (막별 생존)
- 다음 전투 피해량 (`damage_taken`, 층마다 기록됨 — 신호가 촘촘함)

### 4.3 C# 오버레이에 싣기

추천: **Python(PyTorch)으로 학습 → 가중치를 JSON 으로 내보내기 → C# 에서 직접 계산**.
모델이 작다(임베딩 500×16 + 은닉층 2개, 수만 개 숫자). 행렬 곱 몇 번이면 끝나서 화면당 1 ms 미만.

- ONNX Runtime 도 가능하지만 네이티브 DLL(수십 MB)이 단일 exe 배포와 자동 업데이트를 무겁게 만든다. 이 크기 모델엔 손으로 쓴 추론이 더 단순하고, 직접 행렬 곱을 구현해 보는 것도 공부가 된다.
- 팩에 `data/packs/v0.107.1/model/card-policy.json` 로 넣고 `DataPackLoader` 가 읽는다. 파일이 없거나 모르는 카드면 기존 엔진으로 되돌아간다(폴백).
- UI 칩(빌드/필요/콤보 설명)은 기존 `ScoreBreakdown` 을 그대로 쓰고, 순위만 모델이 정한다. 모델 기여분은 `model` 조각 하나로 붙인다.

### 4.4 내 픽에 과적합하지 않기

- 학습·검증 모두 **랭커 데이터만**. 사용자 기록은 학습에 절대 넣지 않는다.
- **플레이어 단위로 나눠 검증** (GroupKFold, 5겹). 같은 사람의 런이 학습과 검증에 동시에 들어가면 그 사람 습관을 외워서 점수가 부풀려진다.
- 승률 모델은 `sample=recent` 만 쓰거나, 일부러 모은 승리 690판에 가중치를 낮춰 자연 승률(25.7%)에 맞춘다. 아니면 모델이 "다들 이긴다"고 배운다.
- 플레이어 실력 교란: 잘하는 사람의 덱이 이기는 건 덱보다 사람 덕일 수 있다. 플레이어별 고정효과(실력 항)를 학습 때만 넣고 추론 때는 평균값을 쓴다.
- 버전: v0.107 과 v0.111 이 섞여 있다. 버전 플래그를 넣고, 패치된 카드는 기존 `drift.py` 목록으로 따로 본다.
- "내 픽과 일치율" 은 100% 목표가 아니다 (기존 규칙). 참고 지표로만 본다.

### 5.2 2단계 결과: 기준선 (2026-11-09)

`python -P tools/CardPolicy/baseline.py <screens.jsonl> <runs_index.csv> --out baseline.json` (18초). 38,847 화면(옵션 5장 이하), 168명, 플레이어 단위 5겹. 모든 수치는 **학습에 안 쓴 플레이어** 기준.

| 모델 | top-1 | 로그우도 | recent 표본 top-1 | 설명 |
|---|---|---|---|---|
| engine (배포 중) | 48.9% | – | 47.9% | 팩의 baseAdjust 가 이 런들로 맞춰졌으므로 **낙관적** (자기 시험지로 채점) |
| engine_noadj | 45.0% | – | 44.1% | baseAdjust 를 뺀 엔진 |
| logit_beta | 46.5% | −1.241 | 45.3% | β·총점 + 막별 스킵 상수만 |
| **logit** | **51.5%** | **−1.142** | 49.4% | 위 + 카드별 보정 δ (훈련 플레이어로만 학습, L2) |

**발견**: 카드별 값 δ 를 제한 없이 쓰는 단순 로짓이 배포 엔진(48.9%, 그것도 낙관적)보다 2.6%p 높다. CARD_CALIBRATION 이 δ 를 팩에 옮길 때 건 제약(tanh 상한 ±10/15, 가이드 불일치 시 절반, 30회 미만 제외, 2겹 분할)이 정보를 깎아 먹는다는 뜻이다. 따라서 3단계 픽 모델의 기준선은 47.2% 가 아니라 **51.5% / −1.142** 다.

남은 누수: 팩의 tier 이동과 dupFactor 도 이 런들로 정해졌다(작음). 완전히 깨끗한 비교가 필요하면 원본 팩(PR #25 이전)으로 다시 추출.

주의 (StS1 사례, 조사 스레드): 랭커 픽 일치율이 가장 높은 모델이 실제 플레이는 가장 못했다. 일치율은 "최소 조건"이지 목표가 아니다. 승률 모델·시뮬레이터 결과와 함께 본다.

**2차 트랙 (사용자 요청, 2026-11-09)**: 전투 시뮬레이터 확장 → 자가대전 RL.
- 10. `sts2.dll` 디컴파일로 몬스터 HP·행동 패턴 추출 (CatalogBuilder 방식), 1막 몬스터부터 `Combat/SimFight` 에 적 턴·인텐트·플레이어 피해 추가.
- 11. 검증: 랭커 런의 전투별 (덱, 몬스터) → 예측 피해 vs 실제 `damage_taken`, 턴 수 비교. 통과 기준을 정한 뒤 2·3막으로 확장.

## 6. 위험과 정직한 예상

- **승률 모델이 별로 안 좋을 수 있다.** 2천 판의 승패는 한 장 한 장의 픽을 판단하기엔 신호가 약하다. 그래서 1단계 목표는 모방학습이고, 승률 모델은 "보너스"로 둔다. 실패해도 픽 모델만으로 지금보다 나아질 가능성이 높다.
- 모방학습은 랭커를 넘지 못한다. 하지만 지금 엔진은 랭커 픽의 47%만 맞히므로, 랭커 수준에 가까워지는 것만으로 큰 개선이다.
- 새 카드·패치 카드는 데이터가 적다 → 30회 미만 등장 카드는 엔진 점수로 폴백.
- 모델은 "왜"를 말해 주지 않는다 → 칩은 엔진 설명을 유지하고, "모델이 엔진과 다르게 고른 이유"는 상위 기여 특징(예: "덱의 독 카드 4장과 상호작용")으로 보여 주는 것을 7단계 이후 검토.
