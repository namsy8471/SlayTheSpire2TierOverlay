# 휴식처 강화 카드 보정 (2026-11)

휴식처에서 "어느 카드를 강화할지" 순위를 상위 랭커의 실제 강화 선택으로 다시 맞춘 기록입니다.
휴식 vs 강화 판단(어느 쪽을 고를지)은 이번에 바꾸지 않았습니다(§5).

## 1. 발단: 지옥검무 빌드에서 천둥을 강화하라고 함

지옥검무(Hellraiser)를 코어로 쓰는 아이언클래드 덱에서 오버레이가 천둥(Thunderclap) 강화를 1위로 추천했습니다.

이전 강화 점수는 두 부분뿐이었습니다.

```
강화 점수 = upgradedDelta(팩에 손으로 적은 값) + 0.2 × 역할 부족(픽 점수의 need)
```

- 지옥검무와 천둥의 `upgradedDelta`는 둘 다 4였습니다(손으로 정한 규칙: "B 이하 4").
- 천둥은 광역(aoe 0.6)이라 덱에 광역이 부족하면 need 몇 점이 붙어 앞섰습니다.
- 빌드 소속(코어·보상 카드인지)은 일부러 넣지 않았습니다. 당시 근거는 사용자 기록 134건에서 빌드 점수의 20%를 더하니
  1위 일치가 28% → 18%로 떨어졌다는 것이었는데, 픽 점수의 빌드 부분을 그대로 섞은 방식이었고 표본도 작았습니다.

랭커 기록에서 이 두 카드는 정반대입니다. 지옥검무는 강화 후보였던 75번 중 30번(40%) 강화됐고, 천둥은 196번 중 4번(2%)입니다.
지옥검무 강화는 비용 2 → 1이라 파워를 일찍 깔 수 있게 해 줍니다.

## 2. 데이터와 방법

- **표본**: OP.GG A10 바닐라 솔로 랭커 런 2,155판(카드 보정 PR #25와 같은 코퍼스, 165명). 그중 휴식처에서 강화하고
  강화한 카드가 기록된 방문 8,140번, 강화 후보 92,568장(방문당 평균 11.4장). 런 파일은 이 PC의 세션 임시 폴더에만 있고
  커밋하지 않습니다.
- **추출**: `RunHistoryAnalyzer upgrade-export`가 각 방문의 덱을 기록에서 복원하고, 강화 가능한 카드마다 한 줄씩
  (`upgradedDelta`, 픽 점수 기본값, 역할 부족, 빌드 역할·commit) CSV로 씁니다. 빌드 역할은 조언기와 같은 함수
  (`UpgradeAdvisor.BuildRoleOf`: 카드가 속한 빌드 중 commit이 가장 높은 빌드)로 읽습니다.
- **모델**: 한 방문의 후보들 사이에서 고르는 조건부 로짓(`tools/UpgradeCalib/fit.py`).

```
효용 = 카드 상수 + Σ 역할계수[역할] × commit + need계수 × 역할 부족
카드 상수 = 사전값 + 카드별 효과(L2 0.3으로 0 쪽으로 당김)
사전값 = upgradedDelta, 강화로 비용 감소, 강화로 키워드 추가/제거, 파워, 기본 카드, 픽 기본값/10 의 가중합
```

  카드별 효과 덕분에 표본이 많은 카드는 자기 기록을 따르고, 드문 카드는 카탈로그 특징(비용 감소 등)으로 정한 사전값 근처에
  머뭅니다. v0.108~0.111에서 바뀐 카드(`tools/CardCalib/drift.py`의 KNOWN)는 새 버전 런에서 따로 효과를 받고 그 값은 버립니다.

- **검증**: 플레이어 기준 2겹 교차검증(한쪽 플레이어로 맞추고 다른 쪽에서 평가, 양방향, 5회 반복).
  점수는 기대 1위·3위 안 일치(동점은 무작위로 나눔)와 평균 로그우도.

| 모델 | 1위 | 3위 안 | 로그우도 |
|---|---|---|---|
| 이전 (upgradedDelta + 역할 부족) | 19.5% | 46.3% | −2.341 |
| 사전값만 | 32.6% | 63.6% | −1.924 |
| 사전값 + 빌드 역할 | 32.8% | 63.6% | −1.921 |
| 사전값 + 카드별 효과 | 42.5% | 77.9% | −1.595 |
| **사전값 + 빌드 역할 + 카드별 효과 (채택)** | **42.9%** | **78.3%** | **−1.587** |
| 참고: 무작위 | 10% | 30% | |

  v0.107 런의 방문(3,274번)만 평가해도 이전 20.4% / 47.3% → 42.3% / 77.8%로 같습니다.
  일치율은 대리 지표이고 100%가 목표가 아닙니다(랭커끼리도 강화가 갈립니다).

## 3. 계수 (로짓, 전체 표본)

| 특징 | 계수 | 뜻 |
|---|---|---|
| 강화로 비용 감소 | +1.81 | 가장 큰 단일 요인 (지옥검무, 육체 숙련 같은 카드) |
| 파워 | +0.82 | |
| 키워드 추가/제거 | +0.76 | 선천성, 보존, 소멸 제거 등 |
| 기본 카드 | −2.63 | 타격·수비는 거의 강화하지 않음 (강타는 카드별 효과로 다시 올라감) |
| 픽 기본값 10점당 | +0.25 | 좋은 카드를 강화 |
| upgradedDelta 1점당 | +0.07 | 손으로 적은 값은 정보가 거의 없음 |
| 빌드 코어 × commit | +1.21 | |
| 빌드 핵심 보상 × commit | +1.09 | |
| 빌드 보조 × commit | +0.66 | |
| 빌드 준비 × commit | +0.62 | |
| 역할 부족 1점당 | +0.05 | 거의 0 |

빌드 역할 계수는 **같은 카드 안에서** 빌드에 들어갔을 때와 아닐 때의 차이입니다(카드별 효과와 함께 맞췄기 때문).
즉 "지옥검무는 원래 좋은 강화"와 별개로 "빌드가 굴러가면 그 빌드의 코어·보상 카드를 더 먼저 강화한다"를 따로 반영합니다.

## 4. 팩에 들어간 값

- `tiers/*.json` 카드마다 `upgradeValue`: `3.68 + 0.586 × 카드 상수`(533장, 1.4 ~ 7.9점). 예: 신격화 7.9, 지옥검무 5.8,
  강타 4.1, 천둥 3.3, 아이언클래드 타격 2.1. 카드 픽 점수는 이 값을 읽지 않습니다(`upgradedDelta`는 그대로).
- `weights.json` `"upgrade"`: `buildRole` 코어 0.71 / 핵심 보상 0.64 / 보조 0.39 / 준비 0.36점(× commit),
  `needWeight` 0.03(역할 부족 부분 배율, 이전 1).
- **척도**: 점수 = A + S × 효용. A, S는 같은 8,140번에서 "후보 평균 점수"와 "1위 후보 평균 점수"가 이전 모델과 같아지도록
  골랐습니다(4.08 / 5.71점). 그래서 순위만 바뀌고, 휴식처 조언기가 강화 점수(1위 후보)와 비교하는 휴식 점수 쪽 균형은
  그대로입니다. 로짓 1당 0.586점이라 빌드 역할 점수가 작아 보이지만(코어 +0.7), 카드 간 강화 가치 차이도 같은 척도입니다.
- 다시 맞추기:

```
dotnet run --project tools/RunHistoryAnalyzer -- upgrade-export <runs-dir> --pack data/packs/v0.107.1 --all-players --out up.csv
python -P tools/UpgradeCalib/fit.py up.csv runs_index.csv --json fit.json --write
```

## 6. 남은 것

- **휴식 vs 강화**: 조언기는 랭커보다 훨씬 자주 휴식을 권합니다(83% vs 42%, HP 50~90% 구간에서 차이 대부분). 휴식 쪽 점수의
  사망 비용이 [추정] 값이라 생기는 쏠림이고, 이번 변경은 이 균형을 일부러 그대로 두었습니다. 랭커 기록으로 따로 맞출 수 있습니다.
- 첫 강화 카드만 봅니다(`upgraded_cards[0]`). 유물 등으로 한 번에 여러 장 강화한 방문은 첫 장만 셉니다.
- 2026-11-13 게임 업데이트 뒤에는 카탈로그와 함께 다시 맞춰야 합니다.
