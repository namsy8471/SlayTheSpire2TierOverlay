## 2. 기능

**게임 안 (보상·상점·시작·이벤트 카드 화면)**
- 카드 왼쪽 위 배지
  - **점수(0~100)**: 현재 런 기준 적합도
  - **티어(S/A/B/C)**: 큐레이션 기본값을 덱 상황으로 보정
  - **최고 픽 하이라이트**
  - 태그 칩 3개
- **스킵 점수**: 덱 크기, HP, 빌드 완성도를 반영
- **상점 유물 배지**: 내 덱에서 그 유물의 영향을 받는 카드 수로 등급 매김 (5장 이상 S / 3장 이상 A / 2장 B / 1장 C)
- 보유 유물과 다음 보스를 점수에 반영
- 마우스를 올리면 점수 분해 툴팁 표시

**태그 체계 (약 40개)**
- 빌드 방향: Keystone, Core, Sub-Core, Finisher, Sustain, Cross-Build, Off-Synergy, Shore Up 등
- 상황: Tempo, Heavy, Burst, Rare Pick
- 중복: Duplicate, Dup. OK, Stack ++
- 경고: Oversat(파워 과다), Random

**사용자 설정**
- `%APPDATA%\Sts2CardAdvisor\card_tier_overrides.json`에서 티어 덮어쓰기
- 14개 언어 태그 번역 덮어쓰기
- ModConfig 연동

**웹 대시보드**
- 전체 카드 카탈로그: 축 태그, 강화 미리보기, 빌드 코어 가이드
- "내 픽" 가상 덱 시뮬레이터: 레이더 차트, 다음 추천
- **런 분석**: 실제 `.run` 파일을 읽어 보상마다 내 선택을 판정
  - 판정 등급: 최선 / 차선 / 고립 / 풀 최저 / 스킵이 나았음 / 저주
- 모드가 `localhost:8765`에 HTTP 서버를 열어 대시보드와 실시간 동기화

## 3. 점수 모델 (대시보드 데이터·JS 기준)

**데이터 (`dashboard.json`, v0.103.2, 카드 1,117개 = 기본 + 강화본)**
- **카드**: `id`(CARD.XXX), 이름, `tier`, **`axes` / `upg_axes`**, 비용, 피해·방어 수치, `expected_value`(카드 수치로 계산한 기대값)
  - 앵커 점수 `anchor_score`와 근거 신호 S1~S8: 배수 효과, 파워 전역성, X코스트, 중심성, 희귀도, 티어, 빌드 주력 여부, 필러 여부
- **축(axes) 190개**
  - 자원별로 **생산자(PRODUCER) · 소비자(CONSUMER) · 증폭기(AMPLIFIER) · 페이오프(PAYOFF)** 역할로 나뉨
  - 예: `POISON_PRODUCER`, `STAR_PAYOFF`, `CUNNING_CONSUMER`(교활 수요), `COST_ENABLER_SKILL`
- **`role_needs` (124개)**: "이 축을 가진 카드는 어떤 축의 짝이 필요한가"를 가중치로 정의
  - 예: 독 생산자 → 독 수요 2.5, 독 증폭기 2.5, 광역 독 2.0, 드로우 0.8
  - `requires_with`(AND 조건)와 `mutex_group`(최대값만 인정)도 있음
- **아키타입 22개**: 슬롯(필요 축과 이상적인 장수와 가중치) + 키스톤 카드 목록
  - 예: 중독 = 독 생산 4장, 독 증폭 2장, 독 소비 1장, 광역 독 1장, 드로우 2장
  - 디펙트는 구체·번개·냉기·어둠·유리·파워·0코로 7개까지 세분화

**계산 흐름**
1. 덱 카드의 축들이 요구하는 짝 역할(`role_needs`)을 모읍니다.
2. 후보 카드가 그 역할을 채우면 점수를 더합니다. 같은 역할을 k장이 요구하면 `w × (1 + 0.3·log2 k)`로 체감 누적합니다.
3. 진행도 phase(0~1)를 `max(층/45, (덱−10)/25)`로 계산합니다. 초반에는 즉효 카드를, 후반에는 페이오프를 가중합니다.
4. **덱 비대 감쇠**: phase가 0.3 이상이고 실효 덱이 20장을 넘으면 점수 × `max(0.78, 1 − 0.012 × (덱−20) × phase)`
   - 드로우·에너지·회복·무형·방어 카드는 감쇠에서 제외
5. 의존 축이 덱에 없으면 감점합니다 ("외부빌드").
6. **스킵 기준** (대시보드): 현재 덱 카드 점수의 **중앙값** + 덱 크기 압력
   - 압력: 15장 초과부터 장당 0.5, 25장 초과부터 장당 추가 0.25, 상한 12
   - 게임 안 스킵 점수는 다른 공식(픽 쪽으로 기울어짐)이라서, 두 값이 달라 사용자 혼란이 있었습니다.

## 4. 사용자 평가 (Nexus 댓글)

**좋은 점**
- 분석적 접근
- 디펙트 추천이 "내 선택과 놀랄 만큼 비슷"
- 냉기 구체가 필수라는 점을 앎

**문제점** (2026-06-22 승천 10에서 "항상 최고점만 골라 10판" 실험 등)

| 문제 | 사례 |
|---|---|
| **빌드 쏠림 > 당장의 약점 보완** | 아이언클래드는 힘 스케일링만 추천해서 방어 부족으로 사망 |
| **의존 조건 무시** | 사일런트에 버리기 엔진이 없는데 교활 카드를 계속 추천. 드로우가 없는데 Speedster 추천 |
| **자원 과잉 생산** | 리젠트가 별이 이미 넘치는데 별 생성 카드를 계속 추천 (포화 개념 없음) |
| 방어 부재 | 네크로바인더가 오스티 시너지 공격만 모으다 방어 0 |
| 같은 카드군 반복 추천 | 중복 가중이 약하다는 지적 |
| 그 외 | 게임 안 스킵과 대시보드 스킵 수치가 다름, 멀티플레이 오류(개발 중 기능이 섞여 배포됨), 설명문이 장황하고 AI가 쓴 티 |
| 업데이트 중단 | 6/15 이후 업데이트 없음. 7월에 레포에 RL(강화학습) 모니터링 페이지가 생겼다가 비공개 연구 레포로 옮겨짐 |

## 5. 우리 설계에 반영할 점

1. **축 모델 채택**: 카드 역할을 "생산자/소비자/증폭기/페이오프 + 자원 종류"로 태깅합니다. 참고 사이트의 must/rec보다 세밀하고, 새 카드도 자동 태깅하기 쉽습니다.
   - PLAN §6.2 `roles` 옆에 `provides` / `consumes` / `requires`를 추가합니다.
2. **의존 조건 게이트**: 교활 카드는 버리기 엔진, 페이오프는 생산자가 덱에 있어야 가치가 생깁니다. 없으면 "엔진 없음"으로 감점합니다.
3. **포화(체감) 처리**: 자원 생산자가 소비자 대비 과다하면 추가 생산자의 가치를 줄입니다 (별, 단도, 영혼 등). 파워 과다도 감점합니다.
4. **약점 보완 > 빌드 끌림**: 필요(Need) 항목이 빌드 시너지를 이길 수 있게 가중합니다.
   - 방어·드로우 공급이 목표치의 50% 미만이면 빌드 점수 상한을 낮춥니다.
   - 이것이 Deck Compass의 가장 큰 불만점이자 우리가 차별화할 지점입니다.
5. **스킵 공식 일원화**: 실시간 추천과 사후 분석이 같은 공식을 쓰게 합니다.
6. **검증 루프**: 내 `.run` 기록으로 "추천대로 골랐다면" 리플레이 리포트를 만들고, 가중치 튜닝 근거로 씁니다. 댓글에서 요청된 기능입니다.
7. **태그 범례를 게임 안에서**: 배지에 마우스를 올리면 칩 설명을 보여줍니다. 요청이 많았습니다.
8. **창작마당 배포**: Deck Compass는 Nexus 수동 설치만 지원합니다. 공개 배포를 하게 되면 창작마당이 유리합니다.

**데이터 재사용 가능성**: 대시보드 레포는 MIT라서 축 태그·아키타입 슬롯 데이터는 출처를 표시하면 참고하거나 가져올 수 있습니다. 다만 데이터가 v0.103.2 기준이라 갱신이 필요하고, 카드 설명 텍스트는 Mega Crit 저작물이라 제외해야 합니다.
